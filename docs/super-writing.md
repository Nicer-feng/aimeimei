# 超能槑槑模式与最终交付

## v2.32.2：局部修稿

现有超能开关改为本会话的局部修稿授权。仍限固定账号 `default`，沿用既有 API 和布尔响应字段；SQLite 新增默认关闭的 `super_revision_mode`，旧的审稿开关不视为授权。历史检查和终稿继续可看，不运行旧的自动 Flash 复检。

首稿完成后输入明确的短改稿指令，可在输入框上方收到一次本会话提示。开启保留草稿、不发送；拒绝或直接发送不拦截普通聊天。关闭态，以及开启态下的起稿、整篇重写和非局部请求，保持既有生成和联网流程。

当前支持单篇正文的开头、结尾、第 1–10 段，以及给单张分镜表在时长前插入景别列。底稿可来自最近完整回复，或在请求中显式粘贴。修改范围、表格或底稿不明确时不调用模型，Web 保留输入。局部请求不读取整段历史进入模型、不做额外的 Flash 调用；主模型只接收修改指令、目标和必要的相邻内容。输出校验后用原文偏移量合并，其他文字、空白和表格列保持不变。只检查新片段的明确禁词；近似正文字数仅报告实测，不虚设硬区间。解析失败、禁词命中或上游未完整结束时不合并。

后台沿用真实主模型 usage。新修订结果和旧复检都使用 `super_check` 展示，用 `version` 区分。模拟回归不证明真实模型的文风提升或线上实际省量。

## 历史版本与验证记录

下文记录旧版自动复检的历史协议和实验，不是当前局部修稿链路。

v2.32.1 的 `super-postcheck-v6` 提供资料结构保留与一次Flash提示。该版本不将语义稳定性实验当作已通过：模型仍有误报漏报，原稿不会因复检被重写。此前未发布候选、失败结果和参数实验保留在下文。温度0仅做过参数实验，本版本未采用，也未更换模型。

第一版仅绑定个人账号 ID `default`。对话的 `super_mode` 默认关闭，不从本机偏好或上一单继承。关闭后后续请求走原生成链路，客户终稿和已经展示的聊天记录保留；关闭不能消除旧回复对同一会话历史的影响。

## 使用与范围

摸鱼按钮旁的“超能槑槑模式”可切换当前对话；关闭态标明“原流程”。“最终交付”可粘贴、上传文本/办公文件，或载入当前聊天消息；保存客户确认的新版本，旧版本保留。同一任务可用名称区分多个博主稿。

保存开关、粘贴和更新终稿不调用语言模型。办公文件复用既有文档上传与解析服务，不自动绑定为每轮聊天附件；文件解析可能有供应商服务费用。无法确认解析内容完整时拒绝直接存为完整终稿，仍可粘贴正文。

客户确认稿与历史推定稿独立标记。未回传时，只读提取本单最近交流中的完整正文或分镜台词，排除标题、评论清单和问答，结果不等于客户验收。交付稿保留版本回看和后续复盘用途，暂停从其他对话检索或向生成请求注入历史范例；同单上传稿也不自动变成本轮要求或主模型底稿，不会因为回传达到某个数量而自动恢复。已有文件、版本和历史参考统计保留。客户接受一个任务的稿件，不等于该稿的口吻、结构或限制适用于其他客户。

## 生成与费用

开启后使用已配置的 `qwen3.8-flash`，不可用时再选择 `qwen3.8-omni-flash`，辅助模型无Key或不可用则降级并提示。主模型仍是当前对话所选模型。

1. 超能模式不调用前置要求整理模型，不注入额外写作指令，不用整理摘要替换原始需求。保持同一设置下原流程的主模型请求；用户另行启用的既有写稿模式、搜索和上下文设置仍按原流程执行。
2. 主模型正常生成一次。当前交付策略仍会等后置检查结束再显示正文，原稿字节不因超能检查而改变；这不保证首字等待与关闭模式相同。
3. 生成后识别标题/封面、发布文案和正文，仅按明确正文范围计数；多篇分别统计，分镜统计台词。存在标题/发布字段但正文边界不明时标记未完成计数，不把整份输出当正文。正文计数排除末尾独立话题，保留正文内的井号内容；口径为含标点、不计空白。
4. 代码只核对本单原始要求中的明确字数和逐字词项，保留原句出处、变更与取消顺序。“正文约750字”展示目标和实际，不自造700–800字硬门槛；明确范围/上下限才触发超限提示。明确只输出结尾等局部内容时，不套整稿字数及必带内容覆盖；“这次不限字数”取消旧限制。限定标题等分区的词项暂标未核对，不扩大成全稿禁词。自然、有观点、少广告味、不要照搬资料结构等不转换成必带词或结构评分。
5. Flash无论长短稿均至多调用一次，不做候选投票或第二轮反证。发送本单完整原始材料和原稿，按编号定位，不摘要替换，也不重复发送代码提取的要求和计数结果。只返回具体疑点，同一句多个独立问题分别保留，不输出逐句通过标签或自报风险覆盖。材料缺证与已证伪分开，不要求模型为“材料未提供”编造来源引文。不做文风评分，不继承其他客户标准。代码只能验证出处和协议，不能据此证明语义正确或全需求覆盖。仅`issues`为必需字段，可选`incomplete:true`只标未完成并保留有效单项；单项位置无效不会清空其他项。响应不可解析仍降级为确定性检查。所有模型意见均待核对，界面不把协议完成称为事实全正确。
6. 后置检查只返回检查记录，不自动触发Max修复，也不执行超能局部合并或分镜替换。界面区分“规则检查”和模型“待核对”；没有发现问题也不表示全面正确或客户验收。用户明确发起改稿仍走正常主模型流程。

开启可能增加等待。超长原始材料或稿件超出当前辅助范围时仍保留原生成并标记检查未完成，不静默截断后宣称完整处理。超能模式不改变既有智能上下文摘要的触发、输入和水位，不承诺原流程从不摘要；本轮原始输入不由新增的整理模型替换。

后审独立读取本单原始用户消息，不只保留最近12条，也不使用主流程的摘要作为事实依据，以免丢失早期价格、条件等更正。超过80条用户消息、合并材料超过70000字符或已知附件材料不全时，不调用Flash；明确标记范围不足，只检查能够确认的本轮规则。该读取只影响后审，不修改主请求。

每次辅助响应收到供应商usage后，立即以真实模型ID、当时价格、缓存计数记入当前对话的system记录与daily_usage；主生成失败不丢已知辅助费用。辅助记录不出现在普通聊天或后续模型历史中。主/辅助用量合并展示，但数据库逐调用保存，避免重复累计；后台摘要也归当前对话。供应商未回usage时记录`usage_unknown`，不推算token或声称零消费。费用依后台配置单价估算，不代表实际账单，解析文件等非LLM费用不纳入token估算。

## 接口合同

所有接口都检查登录用户、固定账号、会话归属、归档状态和生成互斥锁，其他账号返回404。

- `GET /api/conversations/{id}/super-writing`：返回`eligible、enabled、revision、delivery、versions、reference_status、pipeline_version`。
- `PATCH /api/conversations/{id}/super-writing`：请求`{revision, enabled}`，开关必须为布尔值；版本过期返回409。
- `GET /api/conversations/{id}/final-deliveries`：读取相同工作区及终稿历史。
- `POST /api/conversations/{id}/final-deliveries`：请求`{revision, content?, document_id?, filename?, label?}`；保存新客户版本，同名称旧版本标记被替代。正文上限100000字符；文档必须属于当前用户并解析完成。
- `POST /api/conversations`：可带布尔`super_mode`，默认false；其他账号申请开启返回403。
- 消息新增`super_check`，包含有限检查状态、说明、问题、是否局部修复、规则版本和用量未知标记。`message_saved.usage`及历史回复usage包含本轮已知辅助用量；会话总量另含后台摘要等实际调用，聊天轮数不包含辅助记录。

既有SQLite列与表为幂等附加迁移，不改写已有消息。本候选没有超能前置整理阶段；另外开启的既有写稿模式保持原有行为。

## 单次复检的归因对照，仍未发布

用户随后要求先分清平台损耗和模型判断波动，不再增加审核轮次。只读审计证实：此前复制引用与非空来源规则确实过滤过正确意见，v3也确实没有传递具体争议点；但新版福斯“瞬间”和部分背书漏报发生在原始模型返回中。四份材料和原稿均逐字送入接口，相关返回正常结束且远未用完输出上限；这批数据不支持“本轮压缩原文或输出截断导致漏报”的解释。纯文本完整仍不代表表格关系完整，固特异源文本已包含多栏交错，不能仅凭字没有丢就确信对象归属清晰，也不能断言交错是本次后审造成。

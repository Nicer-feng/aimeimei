# 超能槑槑模式与最终交付

第一版仅绑定个人账号 ID `default`。对话的 `super_mode` 默认关闭，不从本机偏好或上一单继承。关闭后后续请求走原生成链路，客户终稿和已经展示的聊天记录保留；关闭不能消除旧回复对同一会话历史的影响。

## 使用与范围

摸鱼按钮旁的“超能槑槑模式”可切换当前对话；关闭态标明“原流程”。“最终交付”可粘贴、上传文本/办公文件，或载入当前聊天消息；保存客户确认的新版本，旧版本保留。同一任务可用名称区分多个博主稿。

保存开关、粘贴和更新终稿不调用语言模型。办公文件复用既有文档上传与解析服务，不自动绑定为每轮聊天附件；文件解析可能有供应商服务费用。无法确认解析内容完整时拒绝直接存为完整终稿，仍可粘贴正文。

客户确认稿与历史推定稿独立标记。未回传时，只读提取最近交流中的完整正文或分镜台词，排除标题、评论清单和问答，结果不等于客户验收。参考库最多筛选近100个相关任务的末16条消息；达到10个不同任务的客户确认稿后停用推定参考。每次仅取最多两个短片段，总参考长度约1800字符，遮去历史数值，并明确禁止借用旧项目事实和限制。第一版没有模型参数训练、无限在线自学习或每轮全量历史分析。

## 生成与费用

开启后使用已配置的 `qwen3.8-flash`，不可用时再选择 `qwen3.8-omni-flash`，辅助模型无Key或不可用则降级并提示。主模型仍是当前对话所选模型。

1. 写稿/改稿前整理本单要求，保留原始本轮用户消息，并保存独立任务状态。标题、评论和普通问答采用较轻的路径。
2. 主模型正常生成一次，候选正文暂不显示，避免用户复制后再被替换。
3. 代码检查明确字数、必带/避用词、局部修改范围和锁稿一致性；Flash根据实际材料做有限复核。
4. 只有稿件原句与材料原句都能定位的问题才允许尝试一次主模型局部补丁，最多三处；局部请求不能改保留段，补丁无效或错误时保留原稿/底稿。不循环重写整篇。
5. 显示交付稿与检查范围。修复不代表再次验收；客户通过也不代表所有事实正确。

开启会增加等待。超长原始材料或底稿超出当前辅助范围时走原生成并标记未完成增强，不静默截断后宣称完整处理。原始本轮输入不会先被摘要替换。智能上下文改为保留摘要水位之后的全部原文，防止固定最近18条挤出尚未摘要的消息。

每次辅助响应收到供应商usage后，立即以真实模型ID、当时价格、缓存计数记入当前对话的system记录与daily_usage；主生成失败不丢已知辅助费用。辅助记录不出现在普通聊天或后续模型历史中。主/辅助用量合并展示，但数据库逐调用保存，避免重复累计；后台摘要也归当前对话。供应商未回usage时记录`usage_unknown`，不推算token或声称零消费。费用依后台配置单价估算，不代表实际账单，解析文件等非LLM费用不纳入token估算。

## 接口合同

所有接口都检查登录用户、固定账号、会话归属、归档状态和生成互斥锁，其他账号返回404。

- `GET /api/conversations/{id}/super-writing`：返回`eligible、enabled、revision、delivery、versions、reference_status、pipeline_version`。
- `PATCH /api/conversations/{id}/super-writing`：请求`{revision, enabled}`，开关必须为布尔值；版本过期返回409。
- `GET /api/conversations/{id}/final-deliveries`：读取相同工作区及终稿历史。
- `POST /api/conversations/{id}/final-deliveries`：请求`{revision, content?, document_id?, filename?, label?}`；保存新客户版本，同名称旧版本标记被替代。正文上限100000字符；文档必须属于当前用户并解析完成。
- `POST /api/conversations`：可带布尔`super_mode`，默认false；其他账号申请开启返回403。
- 消息新增`super_check`，包含有限检查状态、说明、问题、是否局部修复、规则版本和用量未知标记。`message_saved.usage`及历史回复usage包含本轮已知辅助用量；会话总量另含后台摘要等实际调用，聊天轮数不包含辅助记录。

新增SQLite列与表为幂等附加迁移，不改写已有消息。现有写稿模式和超能整理不同时执行，避免双重整理费用。

## 验证与观察

`scripts/test_super_writing.py`使用临时SQLite和真实回环HTTP模拟供应商，覆盖权限、版本冲突、开关、上下文覆盖、局部范围、失败回退、缺usage、摘要与费用归集。`scripts/test_super_writing_ui.js`使用Chrome和模拟接口验证桌面/手机交互、上传、历史与切换隔离。另运行既有写稿、流式、故障恢复和后台趋势回归。

这些测试证明模拟场景中的流程和记账行为，不证明真实供应商可用或客户稿件质量已经提升。第一版保留`super_checks`的流程版本、问题和调用明细；后续可以对比同类型任务的重复纠错、客户回传修改幅度、返工轮数、用量和等待。不能把继续生成标题/评论都算作失败，也不能把未追问都算作好评。

发布保留原文件与SQLite一致性备份。日常回退使用对话开关，不覆盖数据库或删除客户交付版本。
